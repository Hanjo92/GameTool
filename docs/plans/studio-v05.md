# Studio v0.5 implementation contract

All eight requested feature families ship locally through the existing core and three generated runtimes. No remote publication is part of this implementation turn. Existing v1 recipes remain valid; optional `recipe.studio` lives beside legacy layers and composes over them. Shared DTOs/defaults are in `runtimes/shared/studio-types.ts`.

- Flat nodes with unique IDs, optional group parent, absolute-pixel center coordinates, degree rotations, seconds-based start/duration and property keyframes. Group transforms compose; no cycles. Timeline clamps non-loop, repeats using recipe.loop. Studio duration participates in overall playback duration. Old recipe evaluation must not regress.
- Text, image, particles and UI nodes. UI: button, health-bar, cooldown, toast, item-card; normal/pressed/selected/disabled styles and transitions. Canvas pointer hit-test and host APIs expose interactivity. No arbitrary user scripts.
- Scalar data binding (text formatting, values, positions, opacity, visibility, state/color), scheduled named events with scalar payload. Seek is silent; forward playback emits crossed events once; explicit restart resets event traversal. Host owns audio/camera behavior.
- Multiple particle nodes, image sprite-sheet particles, size/opacity/speed lifetime curves, named target x/y data following. Preserve deterministic seed/time and quality budget.
- Editor list, add/delete/duplicate/groups/z-order/lock, timeline tracks/events/bindings, direct canvas transform handles, multi-selection/alignment/grid snapping, in-session undo/redo. Existing panels and presets preserved.
- Quality low/medium/high, reduced motion, bounded instance stress test, actual measured frame timing plus analytic particle/texture estimates clearly distinguished. Three world mode/billboard options; optional Flame component adapter alongside ordinary Flutter widget.
- MCP: batch variants with revision checks and validation before writes, recipe diff, comparison sampling, integration plan/apply with generated-file ownership/hash conflict checks (no arbitrary filesystem paths over HTTP), profiling job. Preview planning before explicit integration apply; parent user requested integration feature, not arbitrary client/game project edits.
- Full acceptance: strict schema/invalid refs/cycles limits; all three source builds; deterministic timeline/seek and data/UI/event fixtures; visual editor and actual runtime smoke; safe regeneration preserves hand edits and unrelated files; old tests remain green. Updated docs, capability metadata, agent skill.

Ownership: root owns shared DTOs, core schema/application/repository, MCP wiring, docs and final integration. Runtime worker owns runtime implementation/renderers/generator. Editor worker owns apps/editor. Workflow worker owns new workflow pure helpers, integration service and focused tests/scripts. Workers must not overwrite others' edits or change shared DTO contracts without coordination.
