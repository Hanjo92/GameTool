# 저장소 공개 준비 보안 검토

검토일: 2026-10-04. 범위는 Git 등록 후보, npm 잠금 파일의 알려진 취약점, 로컬 서비스의 요청 경계, 새 체크아웃의 폰트·스킬 준비 절차다.

## 정리한 항목

- 문서·저장소 스킬의 개인 계정/볼륨 절대 경로를 제거했다. 저장소 스킬은 자신의 설치 위치를 찾고, 별도 복사본은 `--root` 또는 `GAMETOOL_ROOT`를 요구한다. 이미 설치된 전역 스킬이나 다른 MCP 클라이언트 설정은 수정하지 않았다.
- `.env`, 인증서/개인 키, 패키지 인증 설정, 로그, 사용자 지정 작업 공간의 `service.json`/`service.lock`을 Git 제외 규칙에 추가했다. 기존 `.gametool`, `output`, 브라우저 기록, 의존성과 빌드 출력 제외 규칙을 유지했다.
- 약 615 MiB의 폰트 바이너리를 캐시로 제외했다. 기존 로컬 파일은 삭제하지 않았다. 카탈로그·고정 원본 URL·SHA-256·라이선스는 저장소에 남는다. 전체 등록 후보는 약 1.4 MiB다.
- 폰트 복원을 현재 upstream 브랜치 조사 방식에서 카탈로그에 고정된 commit/hash 복원으로 변경했다. 다운로드와 기존 캐시의 해시를 검사하며, 불일치한 기존 파일은 덮어쓰지 않는다. 새 체크아웃에 없는 출력 폴더에 의존하지 않으며 두 한글 기본 폰트도 복원한다.
- `npm run security:repo`는 현재 추적 파일과 미추적 등록 후보를 검사한다. 비밀값 패턴, 개인 경로, 제외 대상의 기존 추적, 대형 파일·바이너리·심볼릭 링크를 보수적으로 보고한다. 탐지 결과에는 파일/행/규칙만 기록하고 일치한 값을 출력하지 않는다.

## 검증 결과

- 등록 후보에서 고신뢰 비밀값 패턴과 개인 경로 검출 0건. 실행 중 서비스 토큰의 정확한 값도 후보 파일에 없음을 별도로 확인했다.
- 검사기의 합성 토큰 탐지 통과, 대표적인 비밀값/생성물 경로 7개 모두 Git 제외 확인.
- `npm audit`: 알려진 취약점 0건(현재 잠금 파일, 총 213개 의존성 메타데이터 기준).
- 외부 Origin, `null` Origin, cross-site 요청, 잘못된 Host, 인증 없는 API 요청, URL 경로 탈출 요청을 실제 loopback 서비스가 모두 HTTP 403으로 거부했다. 서비스 연결 파일 권한은 0600이다.
- `npm test`: 36개 통과. 폰트 다운로드 변조, 기존 파일 변조, 고정되지 않은 원본/다른 호스트 거부 및 기존 파일 보존을 포함한다. `npm run build` 통과.
- 기존 88개 계열의 폰트 163개와 한글 기본 폰트 2개 해시 검사 통과. 빈 임시 폴더에 공식 원본 폰트를 새로 다운로드하고 hash를 검증했다.
- 다른 작업 디렉터리의 저장소 스킬과 명시적 root를 지정한 복사 스킬에서 실제 MCP 도구 19개 조회 통과.
- 검토 시작 시 Git에는 파일이 없는 초기 커밋 1개만 있었으며 원격 저장소는 없었다. 기존 이력과 작업 파일을 보존한다.

로컬 검증 자료는 Git에서 제외한 `output/validation/security-*.log`, `security-portability.json`, `security-repository.json`에 남긴다.

## 신뢰 경계와 사용 조건

GameTool은 신뢰하는 로컬 계정의 작업 공간에서 실행하는 도구다. loopback 바인딩을 유지하고, 작업 공간/연결 토큰/원본 소재를 공개 저장소에 넣지 않는다. 사용자 지정 작업 공간은 저장소 밖에 둔다. 이 검토는 인터넷에 노출하는 다중 사용자 서버나 악의적인 로컬 프로세스에 대한 방어를 검증한 것이 아니다.

HTTP는 Host/Origin/세션 검사를 거치며, GUI와 MCP는 공통 검증·revision 경계를 사용한다. 소재 입력은 바이트를 받고 임의 파일 경로/URL을 읽지 않는다. 빌드는 고정 도구 명령과 분리된 인자로 실행하며 사용자가 제공하는 셸 명령을 지원하지 않는다. 기존 생성물/작업 공간을 신뢰할 수 없는 사람이 수정하도록 공유하지 않는다.

등록 후보 검사는 알려진 패턴 기반이며 모든 형태의 비밀정보를 보장하여 탐지하는 도구는 아니다. 새 파일 추가와 의존성 변경 후에는 `npm run security:repo`와 `npm audit`를 다시 실행한다. 공개 전 파일 목록도 검토한다. 새 커밋 작성, 원격 저장소 연결, 공개 push는 별도의 명시적 사용자 요청에 따라 진행한다.

## v0.5 추가 경계

위 결과는 공개 준비 당시 v0.4 기록이다. Studio 확장에서는 스키마가 노드·키프레임·이벤트·배치·입자·인스턴스 수를 제한하고, 레이어 참조 순환과 비유한 값·위험한 객체 키를 거부한다. 배치는 전부 검증한 뒤 원자적으로 저장한다.

게임 프로젝트 쓰기 권한은 서비스 실행 인자의 `--integration-root`로만 부여한다. MCP/HTTP는 등록 루트 ID와 생성물 ID만 받는다. 계획은 생성 파일 해시와 기존 소유권을 고정하며 적용 시 재검증한다. 수동 편집·소유권 없는 충돌·심볼릭 링크·하드 링크·루트 교체는 거부하고 비소유 파일과 호스트 의존성 파일은 보존한다. 실패 시 임시 디렉터리와 백업으로 복구한다. 악의적인 동시 로컬 파일 시스템 공격에 대한 OS 샌드박스를 제공하는 기능은 아니다.

프로파일러는 loopback의 생성물만 실행하고 외부 origin 요청을 차단한다. 호스트 게임의 오디오·카메라·임의 스크립트는 실행하지 않는다. 전역 에이전트 스킬에는 새 명령 지침을 동기화하되 기존 로컬 설치 탐색 설정을 보존했다. 다른 MCP 클라이언트 설정은 변경하지 않았다.
