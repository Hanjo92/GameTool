# GameTool

게임 UI·이펙트를 편집하고 **Flutter·Phaser·Three.js에서 실행할 코드**로 만드는 로컬 도구. GUI와 stdio MCP가 같은 프로젝트 저장·코드 생성·실행 검증 명령을 사용합니다.

**메시지·트레일러·장소/시간·배경 모션·이미지·파티클**을 함께 편집합니다. 80개 레퍼런스 구성과 기존 10개 프리셋을 제공합니다. 레퍼런스의 메인/서브 타이포그래피, 글자별 움직임, 수면 왜곡·호흡·이미지 전환 등을 실행 코드로 구현했습니다. [레퍼런스 비교와 차이](docs/reference-audit.md)를 확인할 수 있습니다.

- 텍스트: 88개 로컬 서체와 내 폰트, 이중 외곽선·3색 그라데이션, 별도 서브 타임라인, 초 단위 글자 지연·easing·방향·강도. 트레일러 7개 표시 흐름과 페이지·스크롤.
- 장식: 타이틀 틀·박스·코너·띠·경고 테이프·위아래 선·밑줄·사이드 선·바. 독립 등장/퇴장, 부드러운 띠, 둥근 박스, 움직이는 줄무늬.
- 배경: 흔들림·비틀거림·호흡·팬·줌·낙하·흡입·물결·페이드와 이미지 8장까지의 전환.
- 이미지: 정지 PNG/JPEG/WebP 가져오기, 원본 보존, 위치·크기·회전, 27개 색조/이미지 가공.
- 파티클: 기존 눈·불꽃·색종이 + 비·화염·연기·불티·꽃잎·치유·마법 고리·소용돌이·폭죽·충격파 10종. 7개 입자 모양, 4개 방출 영역, 공전·흡입, 색·크기 수명 변화, 발광·가산 합성·잔광, 바람·저항·흔들림.

- 재사용·복구: 프로젝트 복제, 최근 30개 저장 이력과 복원, 내 프리셋 저장/삭제, 문구를 유지한 프리셋 적용.

## 실행

준비: Node.js 22 이상, npm, Google Chrome. Flutter 생성 코드는 SDK 없이 만들 수 있지만 Flutter 미리보기·검증에는 Flutter SDK가 필요합니다. 현재 검증 기준은 Flutter 3.38.7 / Dart 3.10.7, Phaser 3.90.0, Three.js 0.186.1입니다.

```sh
npm ci
npm run fonts:cache
npm run build
npm start
```

브라우저에서 http://127.0.0.1:4317 을 엽니다. 기본 데이터는 Git에서 제외한 `.gametool/`에 저장합니다. 다른 작업 폴더와 포트를 사용할 수 있습니다.

```sh
npm start -- --workspace "/absolute/path/to/workspace" --port 4318
```

프리셋을 고르고 이미지/배경/파티클/문구·모션·시간을 편집하고 **적용 · 미리보기**를 누르면 저장한 소스를 실제 대상에서 빌드·실행합니다. Flutter 첫 빌드는 시간이 걸릴 수 있습니다. **실행 검증**은 분석·빌드·실행·타임라인을 검사하며, **ZIP 다운로드**는 생성 소스와 예제·이미지·폰트·라이선스를 내려받습니다.

SDK나 Chrome이 없으면 해당 작업이 명시적으로 실패합니다. 다른 렌더러로 성공을 대신하지 않습니다. 의존성과 약 615 MiB 폰트 캐시의 최초 설치에는 네트워크가 필요하며, Flutter는 필요한 pub 캐시가 준비되어 있어야 합니다. 로컬 검증은 `flutter pub get --offline`을 사용합니다.

## 파티클 효과

상단 **파티클** → **효과 프리셋**에서 새 효과 10종을 선택하고 **적용 · 미리보기**를 누릅니다. 기본 설정과 용도별 고급 그룹을 열면 28개 고급 설정을 조절할 수 있습니다. 문구 없이 효과만 만들려면 **텍스트 표시**를 끄세요. 검정 미리보기 배경에서 발광을 확인하기 쉽습니다.

- 모양: 원, 별, 빛줄기, 고리, 마름모, 꽃잎, 부드러운 연기.
- 방출: 점, 사각 영역, 원 내부, 고리. 크기는 화면 비율이며 원 반경은 짧은 변을 기준으로 합니다.
- 이동: 방향·중력, 공전, 중심으로 흡입. 바람·흔들림을 더하고 직선 이동에는 저항을 적용합니다.
- 수명: 시작/종료 색과 크기, 크기·속도·수명 편차, 등장/소멸 페이드, 회전.
- 빛: 발광, 일반/가산 합성, 이동 방향의 잔광. 모두 코드로 그리며 이미지가 필요하지 않습니다.
- 시간: 방출 지연, 연속 방출의 채운 시작/빈 시작, 폭발 반복 간격. 0이면 한 번 폭발하며, 양수이면 해당 간격에 새 폭발로 교체합니다. 전체 모션의 페이드와 동기화할지 선택합니다.

기존 설정은 고급 파티클이 꺼진 상태로 같은 움직임을 유지합니다. **기본 모양**을 고르면 기존 동작으로 돌아갑니다. 생성 코드도 같은 시드·시점에서 같은 입자와 잔광을 계산합니다. 현재 파티클은 단일 emitter의 2D 화면 효과입니다.

## 저장·재사용

왼쪽 **저장** 또는 ⌘/Ctrl+S로 빌드 없이 저장할 수 있습니다. **프로젝트 복제**는 현재 편집을 저장한 뒤 새 사본을 엽니다. **저장 이력 · 복원**에서 이전 문구·크기·길이를 확인하고 복원합니다. 최근 30개 이전 저장본을 유지하며 복원 직전 상태도 다시 복원할 수 있습니다. 저장하지 않은 편집이 있으면 먼저 저장하거나 **저장된 설정으로 되돌리기**를 사용하세요. 이력은 기능 도입 후 첫 저장부터 쌓입니다.

**내 프리셋 관리**에서 이름을 입력해 현재 효과를 보관하고, 분류의 **내 프리셋**에서 다시 선택합니다. **프리셋 적용 시 내 문구 유지**를 켜면 메인·서브 문구를 유지하면서 설정을 적용합니다. 내 프리셋은 현재 로컬 작업 공간에 속하며 이미지·폰트를 함께 참조합니다. 프리셋 삭제는 기존 프로젝트와 소재를 변경하지 않습니다.

## MCP

클라이언트 설정을 변경하지 않고 stdio 서버를 제공했습니다. 아래 명령은 프로토콜 외 내용을 stdout에 출력하지 않습니다.

```sh
node scripts/mcp.mjs --workspace "/absolute/path/to/workspace"
```

실행 중인 같은 작업 폴더의 로컬 서비스에 연결하며, 없으면 임의의 빈 loopback 포트에서 서비스를 시작합니다. GUI를 닫아도 사용할 수 있습니다. 자동 시작된 서비스는 MCP 클라이언트가 종료되어도 유지됩니다. 서비스 PID와 연결 정보는 작업 폴더의 `service.json`에 저장되며 토큰을 공유하지 마세요. 해당 PID에 SIGTERM을 보내면 종료합니다.

클라이언트에 넣을 설정 예시(경로를 자신의 설치 위치로 지정):

```json
{
  "mcpServers": {
    "gametool": {
      "command": "node",
      "args": [
        "/absolute/path/to/GameTool/scripts/mcp.mjs",
        "--workspace",
        "/absolute/path/to/GameTool/.gametool"
      ]
    }
  }
}
```

19개 도구: 프로젝트 복제/저장 이력/복원, 내 프리셋 저장/삭제, 이미지·폰트 가져오기/목록, 기능·프리셋 조회, 프로젝트 목록/생성/조회/수정, 코드 생성, 대상 미리보기, 생성물 검증, 작업 조회/취소, 생성 파일 조회. 정확한 입력은 MCP의 tools/list와 [현재 MCP 계약](docs/mcp-contract.md)을 참고합니다.

## 에이전트 스킬

`skills/gametool-effects/`는 다른 에이전트에 전달할 수 있는 스킬 패키지입니다. Codex에서는 원하는 설치 위치의 `skills/gametool-effects/`로 복사할 수 있습니다.

사용 예: **`$gametool-effects로 Three.js용 보스 등장 파티클을 만들고 미리보기와 실행 검증까지 진행해줘.`**

스킬은 연결된 MCP를 우선 사용합니다. MCP가 등록되지 않은 에이전트도 아래 stdio 클라이언트로 같은 Core 명령을 사용할 수 있습니다. 다른 작업 디렉터리에서도 동작하며 클라이언트 설정을 수정하지 않습니다.

```sh
node "/absolute/path/to/GameTool/skills/gametool-effects/scripts/client.mjs" call capabilities_get
node "/absolute/path/to/GameTool/skills/gametool-effects/scripts/client.mjs" --help
```

다른 컴퓨터에는 스킬 폴더와 별도로 GameTool·의존성을 준비하고 `--root "/absolute/GameTool"`를 지정합니다. 자동 스킬 검색을 지원하지 않는 에이전트에는 SKILL.md 경로를 전달해 읽도록 지시할 수 있습니다. 스킬은 프로젝트 수정/소재 입력/파티클/비동기 생성·검증/복구 절차를 설명하며 클라이언트 설정·게임 프로젝트 통합·배포 권한을 추가하지 않습니다.

## 생성물 사용

| 대상 | 소스 | 연결 방식 |
| --- | --- | --- |
| Flutter | `lib/`의 main.dart를 제외한 런타임 파일 | `TextEffect`와 부모 소유 `EffectController`; Flutter Web 예제 포함 |
| Phaser | `src/`와 `assets/` | `new SceneEffect(scene, recipe, await loadImages(recipe))`; Scene update·shutdown 연결 |
| Three.js | 같은 TS 파일 | `effect.object`를 장면에 넣고 호스트 프레임에서 `update(deltaSeconds)` 호출 |

이미지 입력에서 파일을 여러 장 고르면 전환 목록에 추가됩니다. 목록은 ⌘/Ctrl로 복수 선택하고 위/아래 버튼으로 순서를 바꿉니다. 단일 배경 이미지를 다시 가져오면 전환 선택을 초기화합니다.

생성 코드에는 재생·정지·restart·seek·속도 제어가 있습니다. 문구·색은 런타임에서 바꿀 수 있습니다. 생성물은 GameTool이나 MCP 연결 없이 실행하며, 수정한 소스를 다시 생성할 때는 새 출력 폴더를 만들어 원래 파일을 보존합니다.

폰트 캐시를 준비하면 88개 폰트 계열을 로컬에서 사용할 수 있고, 선택한 서체·굵기·기울임과 한글 대체 폰트·라이선스만 생성물에 포함합니다. 캐시를 복구하려면 `npm run fonts:cache`를 실행합니다(복구 시 네트워크 필요). TTF/OTF/WOFF/WOFF2 파일을 등록할 수도 있습니다. 설치 폰트 이름만 지정한 경우에는 대상 기기에 같은 폰트가 필요합니다. 생성물 README의 글꼴 등록 방법도 함께 옮겨야 합니다. Three.js 텍스트는 실행 중 CanvasTexture에 그려지는 HUD 평면이며, 3D 메시 텍스트·WebGPU는 현재 범위가 아닙니다. 배경·입자·장식 텍스트는 Phaser/Three에서 Canvas2D를 매 프레임 그려 엔진 텍스처로 올리고, Flutter에서는 CustomPainter로 그립니다.

## 검증

```sh
npm test
npm run build
npm run smoke
npm run reference:visual
npm run workspace:smoke
npm run particles:visual
npm run skill:smoke
```

`smoke`는 별도 작업 폴더에서 실제 MCP 클라이언트로 세 대상 코드를 생성하고, 정적 분석·빌드·Chrome 실행·시점별 동작을 확인합니다. Flutter는 widget test도 실행합니다. 결과와 실제 소스는 `output/validation/`에 남깁니다. 브라우저 실행 중 외부 origin 요청은 차단합니다.

`workspace:smoke`는 별도 작업 공간에서 실제 MCP의 복제·복원·프리셋 수명과 세 대상 코드 생성 결과를 검증합니다. 결과는 `output/validation/workspace-check.json`에 남깁니다.

`particles:visual`은 Phaser·Three에서 새 효과 10종과 추가 원형 입자를 여러 시점에 렌더하고 역방향 seek 픽셀 재현을 검사합니다. 결과는 `output/validation/particle-gallery/`에 남깁니다.

## 저장소 공개 전 점검

`npm run security:repo`로 등록 후보의 비밀값·개인 경로·제외 대상 추적 여부를 검사하고, `npm audit`로 의존성 공지를 확인합니다. 로컬 작업 공간·토큰·출력·폰트 바이너리는 Git에서 제외됩니다. 폰트는 카탈로그에 고정된 원본과 SHA-256으로 복원하며 라이선스는 저장소에 유지합니다. 사용자 지정 작업 공간은 저장소 밖에 두세요. [보안 검토와 신뢰 경계](docs/security-review.md)를 참고하세요.
